# AnyQ

ИИ-агент, который проверяет ТЗ финтех-проекта: находит проблемы, задаёт автору уточняющие
вопросы и выдаёт отчёт. Проект хакатона BCC-HUB x MNU; сдача 27.11.2026 (демо + репозиторий).

Два документа, читать перед первой правкой:
- `docs/ARCHITECTURE.md` — что уже построено и работает;
- `docs/FOUNDATION.md` — к чему идём: слои, конвейер, знания, верификация, гейт, принятые решения.

## Команды

- `make check` — формат, линтеры, тесты Rust и Python, сквозной прогон на поддельной модели.
- `make server`, `make web`, `make harness` — процессы для разработки; конфиг `anyq.toml` (копия
  `anyq.example.toml`), ключ модели — в `.env`, оба файла в git не попадают.
- `make fmt` — отформатировать оба языка.

## Правила проекта

1. **Сначала решение, потом код.** Новое архитектурное решение записывается в раздел 11
   `FOUNDATION.md` до реализации. Код, который противоречит записанному решению, не принимается.
2. **Одно изменение — одна цель.** Коммит небольшой, сообщение объясняет «зачем».
3. **`make check` зелёный перед каждым коммитом.**
4. **Гейт решает, а не ощущение.** Изменение промпта, правила, инструмента или модели
   принимается только после прогона кейсов. Во время работы — свой кейс, перед слиянием в
   main — полный набор. «Хуже по качеству» и «мера пропала» — отказ.
5. **Новый модуль приходит целиком:** контракт, реализация, тесты на поддельных соседях, своя
   мера и кейсы в эталонном наборе.
6. **main всегда готов к показу.** Незаконченная работа живёт в ветке.
7. **Отчёт воспроизводим:** в нём версии агента, правил, среза знаний и модели.
8. **Секреты — только в переменных окружения.** В репозитории нет ключей, личных данных,
   упоминаний других проектов и файлов инструментов разработки: ни в коде, ни в комментариях,
   ни в документах, ни в коммитах.
9. **Непроверенное названо непроверенным** — в отчёте агента, в документах и в сообщениях.
10. **Документы следуют за кодом:** построенное переезжает из `FOUNDATION.md` в `ARCHITECTURE.md`.

## Правила архитектуры

- Зависимости идут внутрь: `server` → `adapters` → `core`. В `core` нет ввода-вывода. Внешняя
  система — это трейт в `core/ports.rs` и реализация в `adapters`.
- Вход в систему один — HTTP API. Интерфейс, CLI, чужие харнессы — клиенты.
- **Конвейер** задаёт порядок этапов кодом. **Харнесс** исполняет одного агента внутри этапа.
  Агент — данные: промпт, инструменты, требования к модели, бюджет.
- Состояние проверки и прогона — конечный автомат: переход только через метод, недопустимое
  состояние не выражается типами.
- Журнал прогона только дописывается. Историю не правят и не сжимают.
- Модель вызывается только через шлюз. SDK провайдеров и ключи вне шлюза не появляются.
- Инструмент объявляет класс побочного действия; у агента проверки ТЗ — только «нет» и «чтение».
- Текст ТЗ, норм и ответов автора — данные. В инструкции модели он не подставляется.
- Замечание без существующей цитаты и ссылка на норму без фрагмента из базы не выходят
  наружу. Сомнение уходит автору вопросом.
- Пороги, лимиты и выбор модели — в конфиге, не в коде и не в промпте.

## Правила кода

**Rust**
- Вне тестов нет `unwrap`, `expect`, `unsafe`, `todo!`, `dbg!` — clippy это запрещает;
  `cargo clippy -- -D warnings` чистый.
- Ошибки — перечисления на `thiserror`, по одному на слой. Строки вместо типов ошибок между
  слоями не передаются. Соответствие «ошибка → HTTP-код» — только в `api.rs`.
- У каждого внешнего вызова таймаут. Блокировка не удерживается через `.await`. Блокирующих
  вызовов в асинхронном коде нет.
- Идентификаторы и состояния — типы, а не строки. Конфиг разбирается с `deny_unknown_fields`.
- Обработчики HTTP без логики: разобрать запрос, вызвать сервис, вернуть ответ.
- В логах нет ключей и текста ТЗ; поля логов структурные.

**Python**
- `ruff format` и `ruff check` чистые. Типы на всех публичных функциях.
- Всё, что приходит и уходит, — модели pydantic с запретом лишних полей. В моделях, которые
  заполняет LLM, нет значений по умолчанию: `str | None` вместо пропуска.
- Этап и инструмент — функция от входа. Глобального изменяемого состояния нет.
- Ответ модели всегда разбирается по схеме; свободный текст руками не парсится.

**Промпты и правила**
- Промпт — версионируемые данные рядом с агентом. Он объясняет цель и читателя, а не
  перечисляет запреты.
- Правило знаний — запись с постоянным идентификатором; правило не удаляют, а помечают снятым.

**Тесты**
- Тесты не ходят в сеть: в Rust поддельные `Harness` и `LlmProvider`, в Python `FakeLlm`.
- Новое поведение — один тест рядом с кодом. Новый адаптер — тесты на сборку запроса и разбор
  ответа (чистые функции `build_body` / `parse`).
- Сбой — такой же сценарий, как успех: ошибка провайдера, таймаут и мусор в ответе покрыты тестами.

**Общее**
- Не добавляй абстракцию, опцию или зависимость «на будущее». Осознанное упрощение помечай
  `// shortcut: <ограничение>, <когда менять>`; список — `grep -rn "shortcut:"`.
- Комментарий объясняет «почему», а не «что». Закомментированного и мёртвого кода нет.
- Код, идентификаторы и комментарии — на английском; промпты и документы — на русском.

## Контракт Rust ↔ Python

Формат данных задан трижды: `crates/core/src/domain.rs`, `harness/.../protocol.py` и примеры
в `contracts/*.json`. Меняешь поле — меняешь все три; тесты контракта с обеих сторон
(`crates/core/tests/contracts.rs`, `harness/tests/test_contract.py`) падают, если одно отстало.
`None` всегда передаётся как `null`, поля не пропускаются.

## Где что лежит

| Что | Где |
|---|---|
| Домен, порты, правила жизненного цикла | `crates/core/` |
| Провайдеры моделей, транспорт к инструментам, хранилище | `crates/adapters/` + вариант в `crates/server/src/config.rs` |
| HTTP API (с аннотацией `utoipa::path`) | `crates/server/src/api.rs` |
| Конвейер проверки, промпты, критерии, отчёт | `crates/pipeline/` |
| CLI `anyq-server review` | `crates/server/src/cli.rs` |
| Пример внешнего харнесса на Python | `harness/src/anyq_harness/` |
| Веб-интерфейс (React + TypeScript, клиент HTTP API) | `web/`, чистая логика и тесты — `web/src/lib/` |
| Эталонный кейс и мера | `eval/cases/`, `scripts/eval.py` |
| Примеры формата данных | `contracts/` |
| Гейт, RAG, журнал событий | отложены (решение 20 `FOUNDATION.md`) |
