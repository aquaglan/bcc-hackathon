### R-01 — Клиент узнаёт о достижении личного бюджета в момент покупки.

Цитата: «Дать клиенту возможность узнать о достижении личного бюджета в момент покупки.» (Часть A. Новый функционал › Цели, строка 23).

Критерии: ✅ Необходимость · ✅ Уместность · ✅ Однозначность · ✅ Полнота · ✅ Атомарность · ✅ Выполнимость · ✅ Проверяемость · ⚠️ Корректность · ✅ Соответствие шаблону.

- **🟢 Незначительно** · Корректность · Часть A. Новый функционал › Цели, строка 23 · не проверено критиком
  - Проблема: Цель обещает уведомление «в момент покупки». По Ф-2 и критериям приемки расходы учитываются по факту проведения покупки, а проведение может наступить позже: в примере покупка 31 января проведена 1 февраля. По нефункциональным требованиям push уходит в течение минуты после события процессинга, то есть не в момент покупки. Кроме того, термин «личный бюджет» больше нигде не встречается: везде используется «порог».
  - Цитата: «Дать клиенту возможность узнать о достижении личного бюджета в момент покупки.»
  - Исправить: Переписать: «Дать клиенту возможность узнать о достижении месячного порога расходов по карте после проведения покупки, которой порог достигнут».

Ф-3 разрешает максимум один push на карту за календарный месяц. Ф-4 требует push при достижении нового порога независимо от истории, то есть второй push в том же месяце, если первый уже был.

Новый функционал › Критерии приемки, строка 64: Критерий приёмки противоречит Ф-2: месяц определяется по дате совершения покупки по Алматы, значит покупка 31 января должна попасть в январский счётчик, а не в февральский. Это нарушает семантику HTTP: GET-запросы кэшируются, повторяются прокси и предзагрузкой и логируются вместе с параметрами. Настройка может измениться без явного действия клиента. 5. **R-38** · Корректность · Часть B. REST API › Параметры запроса › Request body, строка 147: Для запроса объявлен тип тела application/json, а следующая строка говорит «Тело не используется».
